| 1 | Step 2 redesign: `records.csv`/`regions.csv` now mapped read-only via `mmap` (`src/mmap_file.rs`, hand-declared `extern "C"`, no new dependency) instead of `fs::read`. Removed `src/intern.rs`'s global mutex-sharded `InternTable` entirely. Region join is now a direct-indexed flat `Vec<u16>` keyed by `region_id` -> a packed `[A-Z]{3}` country index (`pack_country`, injective and order-preserving into `0..17,576`, so output needs no separate sort -- ascending index order already matches bytewise-sorted country order). The 8 simple streaming fields (`count`/`id_sum`/`amount_sum`/`min`/`max`/`name_bytes`/`note_bytes`) are now O(1) direct-array updates per thread, no hashmap. `names_distinct` -- the only field needing real dedup -- uses a lock-free two-phase design: phase 1 (12 threads, disjoint mmap ranges, zero shared state) buckets each name into one of 12 shards by `fnv1a(name) % 12`, pushing into its own per-thread-per-shard buffer (no hashmap, no lock); phase 2 (12 threads, one shard each, exclusively -- a name's shard depends only on its own bytes, so no two phase-2 threads ever touch the same name) does exact dedup via `HashSet<&[u8]>` (hash then full byte comparison, never hash-only) and emits a per-country distinct count, summed across shards for the exact global total. Also moved BOM-stripping from a separate whole-buffer copy (`strip_record_start_boms`) into `CsvReader::next()` itself (skip-in-place at each record start), since the old pre-pass would have forced an owned copy to outlive phase 2 and defeated the zero-copy design. Hash-matched byte-for-byte against the cached reference output on seed 1 (`sample` and `full`) and against holdout seeds 2/3/4, native build.
